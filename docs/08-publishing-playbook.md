# چک‌لیست انتشار به‌عنوان GitHub Template Repository

1. یک مخزن **جدید و مستقل** با نام پیشنهادی `research-workflow-toolkit-fa` بسازید؛ **مخزن خصوصی اپ یا پژوهش شخصی را عمومی نکنید**.
2. محتوای این بسته را بدون پوشه والد اضافی، به ریشه مخزن منتقل کنید.
3. پیش از انتشار `python tools/validate.py` و `python -m unittest discover -s tests -v` را اجرا کنید.
4. همه فایل‌های متن، مثال، تاریخچه و اطلاعات شخصی را از نظر افشای ناخواسته بررسی کنید.
5. در GitHub > Settings (پس از ایجاد مخزن) گزینه **Template repository** را فعال کنید؛ این گزینه به دسترسی مدیر نیاز دارد.
6. README و LICENSE را بررسی و در صورت لزوم نام صاحب اثر، راه ارتباطی و سیاست بازخورد را تعیین کنید.
7. برچسب `v0.2.0` را فقط پس از تأیید دروازه انتشار ایجاد کنید؛ در صورت انتشار بدون pilot عامل‌محور، همچنان آن را **template آزمایشی** بنامید.
8. جمع‌آوری مثال‌های اجراشده و گواه‌های آزمون برای نسخه ۰.۳ را آغاز کنید.

این دستورها عملیات دستی و پیشنهادی‌اند؛ ساخت یا انتشار مخزن واقعی در تهیه این بسته انجام نشده است.

9. برای قابلیت استناد، پس از تثبیت انتساب، فایل `CITATION.cff` را کامل و در صورت تمایل GitHub را به Zenodo متصل کنید تا Release آرشیو شود و DOI واقعی بگیرد (مستندات رسمی: https://help.zenodo.org/docs/github/enable-repository/).
