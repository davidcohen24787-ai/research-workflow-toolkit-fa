# معماری کم‌هزینهٔ پژوهش درون‌چت (Subscription-first) — v0.4.0-rc1

## تصمیم

**مسیر پیش‌فرض و توصیه‌شده:** پژوهشگر با اشتراک یا دسترسی موجود ChatGPT یا Gemini، یک گفت‌وگوی معمولی را مطابق دستورالعمل مشترک راه‌اندازی می‌کند. هر مرحله با فرمان طبیعی («مرحله بعد»، «وضعیت»، «بسته انتقال») مدیریت می‌شود و اعتبارسنجی علمی و مجوزهای حساس با پژوهشگر می‌ماند. هزینهٔ API مدل در این مسیر **صفر** است زیرا اساساً هیچ فراخوانی API مدل انجام نمی‌دهیم؛ این ادعا به معنای نامحدودبودن سهمیه اشتراک نیست.

## مسیر پیشنهادی ChatGPT Plus

۱. در ChatGPT یک **Project** برای پروژه پژوهشی شخصی بسازید؛ ۲. متن `chat-first/platforms/CHATGPT_PROJECT.txt` را در Project instructions قرار دهید؛ ۳. دو فایل `chat-first/COMMON_PROTOCOL.md` و `chat-first/WORKFLOW_REFERENCE.md` را اضافه کنید؛ ۴. چت عادی جدید را در همان Project آغاز و دستور «پژوهش جدید: ...» را وارد کنید؛ ۵. در پایان جلسه «بسته انتقال» دریافت و یک نسخه را در فایل شخصی ذخیره کنید. در صورت نبود Project، متن را در آغاز یک Chat عادی استفاده کنید.

**محدودیت جاری:** راهنمای رسمی OpenAI می‌گوید حساب‌های شخصی Plus/Pro در ۲۰۲۶ نمی‌توانند GPT جدید بسازند. GPTهای ازقبل‌ساخته‌شده ممکن است در دسترس باشند؛ لذا راه‌اندازی نباید به ساخت Custom GPT جدید وابسته باشد. کار با Projects در خود ChatGPT انجام می‌شود و نیازمند OpenAI API نیست. حافظه Project و دسترسی به فایل‌ها تابع امکانات حساب و تنظیمات خصوصی‌سازی است.

## مسیر پیشنهادی Gemini / Google AI Pro

۱. یک چت معمولی Gemini باز کنید؛ ۲. متن `chat-first/platforms/GEMINI_CHAT.txt` را در پیام اول قرار دهید؛ ۳. دو فایل مرجع را ضمیمه کنید و موضوع پژوهش را بگویید؛ ۴. در پایان هر مرحله، فایل یا بسته انتقال را برای ادامه در چت بعدی آماده کنید.

Gems فعلاً در حساب‌های واجد شرایط برای دستورالعمل‌های سفارشی پشتیبانی می‌شود، اما طبق راهنمای Google قرار است در **نوامبر ۲۰۲۶** به Skills منتقل شود. به همین دلیل راهکار پایه به Gems یا API نیاز ندارد و فقط در چت عادی راه می‌افتد. قابلیت دقیق بارگذاری فایل/ارجاع به Drive در Gemini تابع حساب و محیط کاربر است.

## ارزان‌بودن ≠ خودکاربودن

| کار | با اشتراک و چت، بدون API | نیاز به دخالت کاربر/محدودیت |
|---|---|---|
| صورت‌بندی، نگارش و خودنقدی یک Chat | بله | ارزیابی علمی و منبع واقعی لازم است |
| استفاده از دستور ثابت در پروژه ChatGPT | معمولاً از Project instructions | نصب دستور و افزودن فایل با کاربر |
| مدیریت چند Chat مستقل | فقط با تحویل/کپی بسته و نظارت دستی یا قابلیت واقعی Work | تضمین کنترل خودکار Chatهای دیگر نداریم |
| انتقال ChatGPT ↔ Gemini | با بسته انتقال متنی + فایل‌های واقعی | **هیچ حافظه مشترک یا همگام‌سازی خودکار وجود ندارد** |
| ذخیره دائمی مدارک | فایل/Drive/Library/Project در صورت دسترسی واقعی | اگر ابزاری نیست، مدل نباید ادعای ذخیره کند |
| جست‌وجو و خواندن مقاله | با ابزارهای در دسترس داخل همان برنامه | دسترسی کامل، هزینه/سهمیه، اعتبار و محل منبع باید احراز شود |
| اجرای عامل کاملاً مستقل با API | **خارج از دامنه این نسخه** | نیازمند توسعه و ممکن است هزینه‌دار باشد |

## پروتکل بازتولیدپذیر

برای هر گذر، کد مرحله، هدف، منبع/نسخه و حدود دسترسی، خروجی واقعی، تصمیم‌های پذیرفته‌شده، عدم قطعیت و اقدام بعدی ثبت شود. چت فقط وقتی ادعای کار انجام‌شده را مطرح کند که خروجی و سند آن **در آن محیط واقعاً موجود** باشد. اگر پژوهشگر با ChatGPT به Gemini رفت، بسته انتقال را صرفاً ادعاهای قبلی بداند و در چت مقصد، خودِ شواهد و فایل‌ها را بارگذاری/راستی‌آزمایی کند.
