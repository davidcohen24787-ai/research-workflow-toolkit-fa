# راهنمای آزمایشگاه تعاملی گردش‌کار پژوهش (نسخهٔ ۰.۳ آزمایشی)

**هدف:** پژوهشگری که برنامه‌نویسی نمی‌داند، از میان ۵ مسیر آماده یا ۱۲ مرحله، یک برنامه اجرایی نسخه‌مند بسازد. این ابزار **پژوهش را اجرا نمی‌کند**؛ به Chat/Work/API متصل نیست و هیچ اقدامی در حساب‌ها انجام نمی‌دهد.

## آغاز به کار بدون نصب

- [صفحهٔ سازنده](index.html) را در مرورگر باز کنید. فایل‌های HTML، CSS و JS باید کنار هم باشند. با دانلود مخزن به‌شکل ZIP و بازکردن `docs/index.html` نیز کار می‌کند.
- عنوان پژوهش را وارد کنید؛ یکی از مسیرهای پنج‌گانه یا «مسیر اختصاصی» را برگزینید.
- شیوه اجرای مناسب را مشخص کنید: یک Chat، چند Chat با هماهنگی، یا عامل‌محور *مشروط*.
- مراحل اختیاری را انتخاب و «ساخت نقشهٔ پژوهش» را بزنید.
- فایل `research-manifest.json` را برای مدیریت وضعیت، فایل Markdown را برای مطالعه و `first-job-card.md` را برای مأموریت نخست دریافت کنید.

## سه خروجی چه تفاوتی دارند؟

**Manifest:** تمام وظایف، ترتیب وابستگی‌ها، دروازه‌های کنترل و وضعیت QUEUED؛ با داده ساختگی یا پیش‌فرض پر نمی‌شود. **Job Card:** دستور خودبسنده برای عامل/Chat واقعی. **نقشه Markdown:** مرور انسانی مراحل. اینها *برنامه* هستند، نه شاهد اجرای کار.

## مسئولیت و حدود

- برنامه‌ریزی از تعریف‌های عمومی `workflows/Wxx.json` و `recipes/*.json` انجام می‌شود، بدون ادعای کفایت روش برای هر زمینه علمی.
- `HUMAN_APPROVAL` هرگز حذف یا خودکار پذیرفته نمی‌شود. خروجی اولیه همه کارها QUEUED است و `public_release_approved` برابر false می‌ماند.
- در حالت عامل‌محور فقط قرارداد وظایف تولید می‌شود؛ Work یا هر ابزار واقعی باید قابلیت، مجوز و محدودیت خود را جدا تأیید کند.
- صفحه برای ساختن برنامه به سرور، کوکی، ذخیره ابری، حساب، کلید API یا تحلیل رفتار کاربر متکی نیست. برای دریافت فایل از قابلیت دانلود محلی مرورگر استفاده می‌کند.
- اشتراک‌گذاری Manifest بعداً نیازمند حذف موضوعات محرمانه و نام اشخاص/داده‌های حساس است. انتشار عمومی همیشه تصمیم پژوهشگر است.
- برای مطالعه انسانی، داده حساس، مرور نظام‌مند یا اجرای آزمایشی، پروتکل علمی/اخلاقی مستقل موردنیاز است. این ابزار جایگزین داوری، ممیزی منابع و مجوز اخلاق نیست.

## آزمون تطابق تعریف‌ها

```bash
python tools/generate_studio_catalog.py --check
node --test tests/test_studio.cjs
python -m unittest discover -s tests -v
```

فایل `docs/index.html` و کاتالوگ خروجی خودکار از تعریف‌های اصلی ساخته می‌شوند تا دو نسخه نامتطابق از مراحل وجود نداشته باشد. پس از تغییر فایل‌های اصلی، `python tools/generate_studio_catalog.py` را اجرا و فایل‌های تولیدی را commit کنید.

## انتشار به‌شکل GitHub Pages

صفحهٔ `docs/index.html` آماده انتشار ایستا است، اما **تا وقتی Pages واقعاً فعال و لینک زنده بررسی نشده، نشانی وب‌سایت عمومی اعلام نمی‌شود**. در تنظیمات مخزن: `Settings → Pages → Build and deployment → Deploy from a branch → main → /docs`. پیکربندی Pages به سطح دسترسی مالک نیاز دارد. فعال‌سازی Pages اختیاری است؛ این نسخه بدون آن نیز از فایل‌های دانلودشده اجرا می‌شود.

## وضعیت اعتبار

آزمون‌های برنامه‌ای ساختار، ترتیب، امنیت نسبی رندر متنی، و برابری گراف وظایف با Python را می‌سنجند. آزمون‌های موجود **اثبات موفقیت علمی پژوهش یا اجرای مستقل چندAgent نیستند**. سنجش با انسان، پایش تجربه کاربری و بررسی میان‌حوزه‌ای باید در مطالعه واقعی و با معیارهای ازپیش‌تعیین‌شده انجام شود.
